# COMMON_WRITING_RULES 원문

Phase 2 `{{common_writing_rules}}`에 통째로 들어가는 공통 글쓰기 규칙. 7개 하위 상수를 아래 순서로 이어 붙인 문자열이다(같은 규칙을 didim-blog-core도 보유 — 여기서는 writer가 단독 동작하도록 원문을 둔다). 본문 속 `\n` 두 글자는 프롬프트 원문 그대로(줄바꿈 문자가 아니라 역슬래시+n 표기)다.

## 목차
1. 조립 순서
2. COMMON_TITLE_RULES — 제목
3. COMMON_HOOK_RULES — 도입부(훅)
4. COMMON_PARAGRAPH_RULES — 문단·번호 목록·소제목·내부 링크
5. COMMON_LEGAL_RULES — 법률 용어·팩트체크
6. COMMON_TONE_RULES — 톤
7. COMMON_EMPHASIS_RULES — 강조·서식
8. CONTENT_TYPE_RULES — 콘텐츠 유형 A~E

## 3. COMMON_HOOK_RULES
````text

도입부 (후킹) 규칙

3~5줄 (100~150자)
제도 설명으로 시작 절대 금지 ("직무발명보상금이란..." 금지)
SEO: 첫 2문장 안에 핵심 키워드 + 숫자 포함 (네이버 검색결과 요약문으로 활용)

■ 훅 (첫 문장) — 아래 6가지 패턴 중 주제에 맞는 것을 선택:
패턴A 결과 제시형: "법인세 2억 원 내던 회사가 8천만 원을 줄였습니다."
패턴B 질문형: "혹시 직무발명보상금이라는 제도, 들어보셨나요?"
패턴C 오해 지적형: "많은 대표님이 이 제도를 모르고 매년 수천만 원을 더 내고 계십니다."
패턴D 대화 시작형: > "우리 회사도 해당되나요?" — 이 질문을 가장 많이 받습니다.
패턴E 뉴스 연결형: "지난주 기획재정부가 2025년 세법 개정안을 발표했습니다."
패턴F 반전형: "특허는 대기업만의 이야기라고요? 매출 30억 중소기업이 특허 3건으로 기업가치를 2배 올린 사례가 있습니다."

■ 두 번째 문장: "어떻게?"를 유발하는 연결
✅ "어떻게 가능했을까요? 얼마 전 만난 제조업 대표님 이야기입니다."

■ 독자 특정 (도입부에 1회):
이 글이 누구를 위한 글인지 명확히 한 문장으로 특정하세요.
✅ "매출 30~100억 규모의 제조업·소비재 기업 대표님에게 특히 도움이 되는 내용입니다."
✅ "창업 3년 이내 스타트업 대표님이라면 반드시 확인하세요."

````

## 4. COMMON_PARAGRAPH_RULES
````text

문단 규칙

한 문단 2~3문장 (5문장 이상 금지 — 모바일 가독성)
단락 사이에 반드시 빈 줄(\n\n) 삽입 — 빈 줄 없이 이어 쓰지 마세요
핵심 키워드 본문 내 3~5회 자연 등장 (6회 이상 = 어뷰징)
스크롤 없이 보이는 첫 화면에 핵심 숫자 1개 이상 배치

■ 번호 목록 작성 규칙 (매우 중요):
번호가 매겨진 항목은 반드시 다음 형식을 따르세요:

**불이익 1. 세제 혜택 소급 취소**

벤처기업으로 인증받으면 법인세 감면을 받습니다.
그런데 인증이 취소되면 이미 받은 혜택이 소급 환수될 수 있습니다.

**불이익 2. 정책자금 지원 제한**

중소벤처기업부 정책자금의 신청 자격이 '벤처기업 인증 유효'를 전제로 합니다.

규칙:
- 각 항목 제목은 **볼드**로 감싸세요: **항목 1. 제목**
- 제목 뒤에 반드시 빈 줄(\n\n) 삽입
- 항목의 설명 본문은 제목과 분리된 별도 문단
- 항목 사이에 빈 줄 2개(\n\n\n) 삽입하여 시각적 분리 강화
- 첫째, 둘째... 또는 1., 2., 3... 또는 불이익 1. 불이익 2... 패턴 가능
- ❌ 금지: 번호와 설명을 한 덩어리로 이어 쓰기
- ❌ 금지: "1. 제목 설명 본문이 이어지는..." 형태

■ 시인성 규칙 (모바일 최적화):
- 소제목 직후 첫 단락은 1~2문장으로 짧게
- 리듬 변화: 짧은 단락 → 보통 단락 → 인용(>) → 짧은 단락. 단조롭지 않게.
- 긴 설명은 불릿(-)으로 분리: 3가지 이상 나열 시 각각 줄바꿈 + 불릿

■ 소제목 규칙:
- 2~3개 사용
- 첫 번째 소제목은 호기심 유발형으로:
  ❌ "기업부설연구소 설립 요건" (정보 나열형)
  ✅ "그런데 대표님이 몰랐던 한 가지가 있습니다" (호기심 유발형)
- 두 번째 이후 소제목은 정보형 가능
- 소제목에 "OO이란?", "OO의 정의" 같은 사전식 표현 금지
- 소제목만 스캔해도 글의 흐름이 파악되어야 함

■ 내부 링크:
- 관련 글 내부 링크 2~3개를 [내부링크] 마커로 표시
- 외부 링크(http://) 사용 금지. 내부 링크만 허용

````

## 5. COMMON_LEGAL_RULES
````text

법률 용어 규칙

법률 용어는 한국어 우선, 필요 시 괄호 안에 법조문 표기
예: "연구·인력개발비 세액공제 (조세특례제한법 제10조)"
법적 근거 없는 법적 주장 절대 금지
전문용어 첫 등장 시 독자 수준에 맞춰 1줄 부연 설명 추가
신뢰 장치 삽입 (글 당 1~2개):
· 법령 근거: "(근거: 조특법 제10조, 2024년 개정)"
· 실적 수치: "디딤에서 지난 1년간 처리한 절세 컨설팅 건수: 40건+"
· 자격 명시: "KAIST 출신, 기업기술가치평가사 자격"

■ 팩트체크 필수 규칙:
- 법조문 인용 시 조/항/호/목까지 정확히 표기. 불확실하면 "(정확한 조항 확인 필요)" 주석 추가
- 기관명 약칭은 공식 약칭만 사용:
  · 한국산업기술진흥협회 = KOITA (KISTA 아님)
  · 한국발명진흥회 = KIPA
  · 중소벤처기업부 = 중기부
  · 한국특허전략개발원 = KISTA (혼동 주의: 산업기술진흥협회와 다름)
- 세법 관련 수치(비과세 한도, 공제율, 세율 구간)는 반드시 "○○년 기준" 명시
- 확실하지 않은 수치에는 "(확인 필요)" 표기. 잘못된 수치보다 불확실 표기가 낫다
- 법률 개정 여부가 불확실하면 "현행 기준"이라고 명시하고 독자에게 최신 확인 권유

````

✅ "얼마 전 제조업 대표님을 만났습니다. 법인세 2억을 내고 계셨는데, 숫자를 보여드리니 눈이 커지셨어요."

## 7. COMMON_EMPHASIS_RULES
````text

강조 및 서식 규칙

볼드(**텍스트**): 핵심 숫자, 결론 문장, 번호 항목 제목에 사용 (문단 전체를 볼드하지 말 것)
인용(>): 고객 실제 발언, 법조문 요약에만 사용
━━━ 구분선: CTA 직전에 1회만 사용
요약 박스: "바쁜 대표님을 위한 3줄 요약" 형식, 본문 말미에 1회
이모지: 요약 박스와 체크리스트 외에는 사용 금지
마크다운 표(| 구분 | 내용 |) 생성 절대 금지. 비교 데이터는 반드시 인포그래픽 이미지 마커로 표현

■ 강조점(불릿) 규칙:
- 항목이 3개 이상이면 불릿(-) 또는 번호(1. 2. 3.)로 나열
- 각 불릿 항목 사이에 줄바꿈(\n) 삽입
- 불릿 항목이 2문장 이상이면 빈 줄(\n\n)로 분리
- 문장 중간에 "첫째, 둘째, 셋째"로 나열하지 말고 각각 줄을 바꿔서 표시
  ❌ "첫째 A이고, 둘째 B이며, 셋째 C입니다."
  ✅ "- 첫째, A입니다.\n- 둘째, B입니다.\n- 셋째, C입니다."

````

## 8. CONTENT_TYPE_RULES
````text

콘텐츠 유형 자동 판단
주제를 분석하여 아래 5가지 유형 중 가장 적합한 것을 선택하고,
해당 유형의 구조 가이드를 따르세요. 유형을 글에 표시하지 마세요.

A. 고객 사례형 — 실제 고객의 문제 해결 스토리
   구조: 훅(결과) → 고객 상황 → 문제 발견 → 해결 과정 → 결과/수치 → 시사점 → CTA
   길이: 2,000~2,500자 / 시각 자료: 2~3개
   적합: 절세 성공 사례, 인증 획득 사례, 특허 전략 사례

B. 제도 해설형 — 제도/법률/요건을 쉽게 풀어쓰는 글
   구조: 훅(핵심 혜택) → 제도 개요 → 요건/조건 → 신청 방법 → 주의사항 → FAQ → CTA
   길이: 1,800~2,200자 / 시각 자료: 3~4개
   적합: 세액공제 제도, 벤처인증 요건, 연구소 설립 절차

C. 뉴스 분석형 — 최신 뉴스/정책에 디딤 전문가 코멘트
   구조: 훅(뉴스 핵심) → 무슨 일인지 → 중소기업에 미치는 영향 → 디딤 코멘트 → CTA
   길이: 1,200~1,500자 / 시각 자료: 1~2개
   적합: 세법 개정, 특허청 정책 변경, AI/IP 관련 뉴스

D. 체크리스트형 — "~하기 전 확인할 N가지"
   구조: 훅(실수 사례) → 체크 항목 1~5 (각 항목당 2~3문장) → 요약 → CTA
   길이: 1,500~1,800자 / 시각 자료: 1~2개
   적합: 세무조사 대비, 연구소 사후관리, 인증 갱신 준비

E. 비교 분석형 — 두 가지 선택지를 비교
   구조: 훅(고민 상황) → 선택지 A 설명 → 선택지 B 설명 → 비교 정리 → 추천 → CTA
   길이: 1,800~2,000자 / 시각 자료: 2~3개
   적합: 벤처인증 vs 이노비즈, 직접출원 vs 대리출원, 연구소 설립 유형별 비교

같은 주제(예: 직무발명보상금)도 매주 다른 유형으로 작성하세요.
A(성공 사례 스토리) → D(대표님이 놓치는 3가지) → B(제도 상세 해설) 순서로 돌리면
독자 피로도가 낮아집니다.

````

## 규칙 간 충돌 (코드 그대로 둔 것 — 작성 시 판단 기준)

| 항목 | 충돌 | 스킬에서의 처리 |
|---|---|---|
