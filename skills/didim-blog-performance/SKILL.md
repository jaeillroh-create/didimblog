# 디딤 블로그 성과·상담·KPI

백오피스의 성과 입력·리드 추적·분석·대시보드를 레포·DB 없이 재현한다. KPI·전환율·집계는 `scripts/` 의 Python 포팅으로 **반드시 계산**한다(원본과 같은 공식·반올림을 쓰기 위해서). `skills/_DECISIONS.md`(Notion DB 구조·선택지, 측정 최소화)를 따른다.

브랜드 규칙은 **didim-blog-core 스킬을 함께 읽는다.** 코어가 없을 때를 위한 최소 원칙:
- 연락처 이메일은 `roh@didimip.com` 하나뿐이다. 상담 기록에 다른 디딤 주소를 만들지 않는다.
- 성과 보고·제안 문구에 절세액·인증·등록 결과를 보장하는 표현을 쓰지 않는다. '특허청'은 '지식재산처'로 쓴다.
- 상담 기록의 회사명·연락처는 내부 기록이다. 블로그 글·공개 자료에 옮기지 않는다(사례 글은 익명화된 사례 메모만).

## 언제 쓰나
- 발행 1주 뒤(매주 금요일 루틴) 글별 성과를 기록할 때
- 상담 문의를 등록하거나 진행 상태·계약을 갱신할 때
- 리드 KPI·전환 기여·키워드 순위·대시보드·월간 요약을 볼 때

## 입력
- 콘텐츠: Notion "디딤 블로그 콘텐츠"(`collection://463bc815-11ab-4290-9d86-22bd1aa9cfed`) 행 — 제목·상태·카테고리·발행일·발행 URL·조회수(최근)·댓글 수·유입 키워드 TOP3·성과 갱신일.
- 상담: "디딤 블로그 상담"(`collection://e1272822-7efd-4850-b8c8-cfce02db7d00`) 행 — 회사명·상담일·유입 경로·경유 글·관심 서비스·상태·계약 여부·계약 금액.
- 키워드: "디딤 블로그 키워드"(`collection://4e0fae54-aeb3-48dd-b948-b78886a8e859`) — 키워드·우선순위·현재 순위·순위 확인일.
- 성과 수치는 사용자가 네이버 블로그 통계에서 보고 알려준다(자동 수집 없음). RSS 는 제목·날짜 확인용.
- 스크립트는 한글 속성명을 그대로 받는다. 속성·선택지·원본 매핑: `references/notion-fields.md`.

## 절차

### A. 글별 성과 입력 (금요일 루틴)
1. 이번 주(또는 지정) 발행 글을 찾는다. 사용자에게 조회수, 유입 키워드 TOP3, 댓글 수(선택: 이웃 추가 수)를 받는다.
2. `python3 scripts/dashboard_kpi.py snapshot --views-1w 320 --comments 4 --top-keywords "a,b,c" [--neighbor-added 2] [--to-s5]`
   → `notion_content_update`(조회수(최근)·댓글 수·유입 키워드 TOP3·성과 갱신일[KST], 필요 시 상태 `S5 성과측정`)를 그대로 쓴다.
3. S4→S5 전이는 발행 후 7일 이상이어야 한다 — didim-blog-ops 의 `transition_check.py check --to S5` 로 확인한 뒤 `--to-s5` 를 쓴다.
4. 이웃 추가 수는 저장 열이 없다 → 보고에만 넣는다. "상담 유입 있음"이면 B 절차로 상담 DB 에 경유 글과 함께 기록한다.
5. 이상치(전주 대비 급증·급감)가 있으면 원인 후보(검색 노출 키워드, 공유, 계절성)를 한 줄로 붙인다(주간 루틴 '이상치 원인 파악').

### B. 상담(리드) 등록·갱신
1. 새 상담: `python3 scripts/leads_kpi.py new-lead --input lead.json --today YYYY-MM-DD`
   - 회사명 필수("회사명은 필수 입력 항목입니다."). 유입 경로는 블로그/지원매치/특허인증센터/소개/기타, 관심 서비스(다중)는 출원·심판/지원사업 가점용 특허·인증/절세·연구소/기타, 상태 기본 '신규'.
   - 경유 글은 유입 경로가 '블로그'일 때만 연결한다(원본 규칙). 블로그 유입이면 어떤 글을 보고 왔는지 꼭 묻는다 — 전환 기여 분석의 근거다.
   - 결과 `notion_row` 를 상담 DB 에 쓴다(담당자명·연락처는 메모에 함께).
2. 진행 갱신: 상태를 신규 → 진행 중 → 제안 → 계약 / 보류 / 종료 중 하나로 바꾸고, 계약이면 `계약 여부`와 `계약 금액`(원)을 함께 쓴다.

### C. 리드 KPI·전환 기여
1. `leads_kpi.py stats --leads leads.json` → 총 리드 수, 상담 전환율(S3→S4) = round((S4+S5)/전체×100), 계약 전환율(S4→S5) = round(S5/(S4+S5)×100), 누적 계약금액(계약 여부=예이고 금액 있는 건 합), 단계·유입 경로·관심 서비스 분포. 단계 매핑: 신규=S3, 진행 중·제안·보류·종료=S4, 계약=S5.
2. `leads_kpi.py attribution --leads leads.json --contents contents.json` → 경유 글별 상담·상담 진행·계약·계약금액, 조회수 대비 상담 비율(스킬 보완 지표). 블로그 유입인데 경유 글이 비어 있는 건수도 알린다.

### D. 키워드 순위
1. 사용자가 네이버에서 확인한 순위를 받는다(TOP 100 밖·미노출이면 비움).
2. `leads_kpi.py keyword-rank --keywords kw.json --new-ranks new.json --now YYYY-MM-DD [--only-high]` → 이전 순위 대비 변동(이전 − 새 순위, 양수=상승)과 `notion_keyword_updates`(현재 순위·순위 확인일)를 쓴다. 이전 값은 덮어쓰므로 변동은 보고에 남긴다. 원본은 우선순위 HIGH(높음) 키워드만 추적했다.

### E. 대시보드·월간 요약·분석
`dashboard_kpi.py` 의 하위 명령에 `{"contents":[…], "leads":[…]}` 를 넣는다.
- `dashboard --now <ISO>` : 이번 주 발행(일요일 시작 7일, S4·S5)/주간 목표(기본 1편 — 결정 사항, 원본 상수 3), 월간 조회수(전체 글 조회수 합), 평균 품질점수, 활성 리드(S3·S4 = 신규·진행 중·제안·보류·종료), 총 콘텐츠.
- `summary --now <ISO>` : 조회수 합계(발행 글 조회수(최근) 누계), 이번 달 상담 건수(상담일 ≥ 이번 달 1일), 이번 달 계약 건수.
- `top-posts` : 조회수 TOP 5 + 글별 상담 건수.
- `analytics` : 월별 추이(발행월별 조회수·전환 합)와 최근 2개월 비교 카드(조회수·평균 체류시간·발행 건수·전환율, 전월 대비 %). 평균 체류시간은 저장하지 않으므로 0 으로 나온다고 밝힌다.
- `rankings` / `radar` / `quality --month YYYY-MM` : 품질점수(조회수 40%·체류시간 30%·전환 30%, 월 최대 대비 정규화; 80+ 우수·60+ 양호·40+ 보통·20+ 미흡·그 아래 위험) 기반 TOP 10·하위 5, 카테고리 비교. 체류시간·CTA 클릭은 기록하지 않으므로 사용자가 값을 줄 때만 의미가 있다.
- 업데이트 필요 글 목록은 didim-blog-health(`content_health.py update-needed`), 이번 달 카테고리별 발행 현황은 didim-blog-ops(`calendar_ratio.py progress`)로 받아 함께 보여준다.

## 출력 형식
- 성과 입력: 표(제목 | 조회수 | 댓글 | 유입 키워드 TOP3 | 성과 갱신일) + Notion 반영 내역 + 이상치 메모.
- 상담: 저장한 행(회사명·상담일·유입 경로·경유 글·관심 서비스·상태) 확인 표.
- KPI: 카드 4개(총 리드·상담 전환율·계약 전환율·누적 계약금액) + 파이프라인 표 + 분포.
- 대시보드: KPI 카드 + 월간 요약 3수치 + TOP 5 표 + (health·ops 결과) 업데이트 필요 글·월간 발행 현황.
- 숫자는 천 단위 쉼표, 금액은 "원", 비율은 정수 %(원본 반올림), 전환율 카드만 소수 둘째 자리.

## 금지·주의
- 성과 수치를 추정·생성하지 않는다. 사용자가 준 값만 쓴다.
- 상담 개인정보(연락처 등)를 블로그 초안·사례 글로 넘기지 않는다.
- 별도 성과 DB 를 만들지 않는다. 메모 열에 쓰지 않는다(사람 전용).
- 계약 금액 합계에는 '계약 여부'가 체크된 건만 넣는다.
- 원본 대시보드의 월간 조회수는 기간 필터 없이 누계다 — '이번 달'이라고 단정하지 말고 누계임을 밝힌다.
