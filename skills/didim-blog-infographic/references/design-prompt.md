> 이 프롬프트는 코드 원문이 아니다. 원본 `PHASE25_INFOGRAPHIC_PROMPT`(`legacy-code-rules.md` 2절)의 단계 구조(데이터 추출 → 유형 매칭 → 다양성 검증 → 위치 → 출력)를 유지하고, 내용은 `rules-v2.md`로 바꿔 재구성했다. 바꾼 점: "정확히 N개" → 카테고리별 범위, 한국어·영문 이중 프롬프트·감정 톤·색상 자유 선택 삭제, 출력 항목을 v2 8항목으로, 썸네일 규칙을 v2 T 규칙으로.
> 스킬에서는 Claude가 이 지시를 직접 따른다(별도 LLM 호출 없음). 다이어리에는 쓰지 않는다.

## 프롬프트

```
당신은 특허그룹 디딤 블로그의 인포그래픽 설계자입니다.
아래 완성된 본문을 읽고, 썸네일 1개와 본문 인포그래픽을 '인포그래픽 규칙 v2'에 맞게 설계하세요.

## 1단계: 시각화 후보 데이터 찾기
본문 전체에서 아래 조건 중 하나 이상을 만족하는 데이터만 후보로 고릅니다.
- 비교할 수 있는 숫자 쌍 (적용 전/후, A안/B안)
- 핵심 수치 3개 이상
- 3단계 이상의 절차
- 요건·조건 5개 이상
- 제도·기관 사이의 구조
개수를 채우려고 약한 데이터로 인포그래픽을 만들지 않습니다.

## 2단계: 유형 고르기
| 데이터 | 유형 | 필수 데이터 |
|---|---|---|
| 적용 전/후, A안/B안 | A. 비교 | 비교할 숫자 쌍 1개 이상 |
| 신청 절차, 업무 흐름 | B. 프로세스 | 3~5단계 |
| 핵심 수치 요약 | C. 숫자 카드 | 수치 3~4개 |
| 기한, 개정 연혁 | D. 타임라인 | 날짜·기간 3개 이상 |
| 자격 요건, 준비 서류 | E. 체크리스트 | 항목 5~7개 |
| 단계별 탈락·전환 | F. 퍼널 | 단계별 수치 3개 이상 |
| 제도·기관 관계 | G. 구조도 | 주체 3개 이상과 관계 |
| 항목별 금액·비율 | H. 수평 막대 | 같은 단위 수치 3~6개 |
이 카테고리의 우선 유형: {{priority_types}} (데이터가 맞을 때만)

## 3단계: 개수와 다양성
- 썸네일(T) 1개 + 본문 인포그래픽 {{body_count_range}}
- 같은 유형은 한 번만, B(프로세스)와 F(퍼널)는 함께 쓰지 않음

## 4단계: 위치
- 썸네일은 "top"
- 본문 인포그래픽은 그 데이터를 설명하는 문단 바로 뒤, 문단 ID "p:N"
- 이미지 사이에 문단 최소 2개. CTA 바로 앞에는 요약형(A 또는 C)을 권장, 데이터가 없으면 생략

## 5단계: 글자 (모든 이미지 공통)
- 이미지 속 숫자(금액·비율·기간·연도·조문 번호)는 본문에 같은 표기로 있는 것만. 반올림·새 숫자 금지
- 결과 보장·단정 표현 금지 ("절감합니다", "100% 등록", "무조건"). 사례·범위 표현 사용
- 헤드라인 20자 이내, 항목 라벨 10자 이내, 강조 수치 5개까지, 강조는 1~2곳
- 브랜드는 "특허그룹 디딤"만. 전화·이메일·URL·다른 브랜드 금지. 기관명은 '지식재산처'
- 이모지 금지

## 썸네일(T)
- 메인 문구: 글 제목의 핵심을 2~3줄, 한 줄 6~9자(최대 10자), 의미 단위로 끊기
- 제목을 그대로 옮기거나 "N가지", "완벽 가이드" 같은 제목 공식을 쓰지 말고 독자의 질문·상황으로
- 가장 중요한 단어나 숫자 하나만 강조. 서브문구는 선택, 1줄 12~18자
- 수치 비교표·체크리스트·절차 도식은 넣지 않음

## 카테고리: {{category_name}}
## 키워드: {{target_keyword}}

{{phase2_output}}

## 출력 (JSON 배열만, 설명 없이)
각 이미지마다 아래 8항목. texts는 이미지에 들어갈 모든 글자이며, 여기 없는 글자는 이미지에 넣지 않습니다.
texts 순서: T=[태그, 메인 줄…, (서브문구)] / A=[라벨A, 값A, 라벨B, 값B, (차이)] / B=["제목|설명", …] /
C·D·F·H=[라벨, 값, 라벨, 값, …] / E=[항목, …] / G=[중심 주체, "주체|관계", …]
[
  {
    "type": "T 또는 A~H",
    "position": "top 또는 p:N",
    "headline": "20자 이내, 독자가 얻는 메시지",
    "texts": ["..."],
    "data_source": ["texts 수치가 나온 본문 문장을 그대로"],
    "emphasis": ["texts 안의 값 1~2개"],
    "footnote": "출처(법률·기관) · 기준일 · 단위. 사례면 '개별 상황에 따라 다름'",
    "alt": "20~40자, 핵심 키워드를 앞에"
  }
]
```

## 예시 (v2 문서의 A. 비교 예시 그대로)

```json
{
  "type": "A",
  "position": "p:7",
  "headline": "같은 이익, 법인세가 달라진 사례",
  "texts": ["적용 전", "법인세 2억 원", "적용 후", "법인세 약 5,000만 원", "약 75% 감소"],
  "data_source": ["법인세 2억 원을 내던 제조업체가 직무발명보상금 제도를 적용한 뒤 약 5,000만 원으로 줄었습니다"],
  "emphasis": ["법인세 약 5,000만 원"],
  "footnote": "매출 80억 원 제조업 사례 · 조세특례제한법 기준 · 개별 상황에 따라 다름",
  "alt": "직무발명보상금 적용 전후 법인세 비교 인포그래픽"
}
```
주의: v2 예시의 "약 75% 감소"는 data_source 문장에 없다. 본문 다른 문장에 "약 75%"가 있으면 그 문장도 data_source에 넣는다(`check_sources.py`가 경고함).
