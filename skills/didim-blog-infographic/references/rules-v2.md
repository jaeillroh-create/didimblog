# 디딤 블로그 인포그래픽 규칙 v2

Oct 1, 2026 · @재일

## 개정 요약

v2는 기존 규칙끼리 부딪치던 6곳을 하나의 규칙으로 정리했습니다. 가장 큰 변경은 설계 단계와 그림 단계가 같은 규칙을 따르게 한 것입니다.

| 충돌 지점 | 기존 | v2 |
| --- | --- | --- |
| 이미지 속 글자 | 설계는 "글자 전부 한국어", 그림 단계는 "글자 없음" | 글자는 한국어로 넣되, 정확한 한글이 필요하면 코드로 합성 |
| 개수 | 규칙은 1\~5개, 코드는 정확히 3개 + 썸네일 | 본문 데이터에 따라 0\~3개 + 썸네일 1개 |
| 다이어리 | 규칙은 사진 1\~2장, 설계 단계는 인포그래픽 3개 | 다이어리는 설계 단계를 건너뛰고 분위기 사진만 |
| 비율 | 16:9, 1:1(1080px), 1024×1024가 섞임 | 썸네일 1:1, 본문 4:5, 모두 폭 1080px |
| 색상 | 썸네일 색상이 하드코딩, 앱 토큰과 다름 | 블로그 이미지 전용 팔레트 상수 하나로 통일 |
| 헤드라인 표현 | 예시는 "6천만 원 절감한 방법", 썸네일 규칙은 결과 확정 표현 금지 | 모든 이미지에 변리사 광고 규정 적용, 사례·범위 표현 사용 |

## 공통 원칙

이 다섯 가지는 썸네일과 본문 인포그래픽 모두에 예외 없이 적용합니다.

1. **한 곳에서만 정합니다.** 비율·색상·글자 규칙은 이 문서가 기준입니다. 설계 단계와 그림 단계 프롬프트는 이 규칙을 그대로 따르고, 서로 다른 값을 두지 않습니다.
2. **이미지 속 숫자는 본문에 그대로 있어야 합니다.** 금액·비율·기간·연도·조문 번호는 본문에 같은 표기로 나오는 것만 씁니다. 본문에 없는 숫자를 만들거나 반올림으로 바꾸지 않습니다. 추정치는 "(E)" 또는 "약"을 붙입니다.
3. **변리사 광고 규정을 지킵니다.** 결과를 보장하거나 단정하는 표현은 금지입니다.
   - ❌ "법인세 6천만 원 절감합니다", "100% 등록", "무조건 승인"
   - ✅ "법인세를 약 6천만 원 줄인 사례", "최대 25% 세액공제", "요건 충족 시 가능"
   - 사례 수치를 쓸 때는 하단 주석에 "개별 상황에 따라 다름"을 넣습니다.
4. **글자량을 제한합니다.** 모바일 화면에서 읽힌다는 것을 기준으로 합니다.
   - 헤드라인 20자 이내, 항목 라벨 10자 이내
   - 이미지 한 장에 강조 수치는 5개까지, 강조색은 1\~2곳
   - 가장 작은 글자도 이미지 폭의 2.5% 이상 (1080px 기준 약 28px)
5. **브랜드 표기는 "특허그룹 디딤" 하나입니다.** 전화번호·이메일·URL·다른 브랜드명은 이미지에 넣지 않습니다. 상담 안내는 본문 CTA가 맡습니다. 기관명은 '특허청'이 아니라 '지식재산처'로 씁니다.

## 개수와 배치

썸네일 1개는 항상 넣고, 본문 인포그래픽은 본문에 시각화할 데이터가 있을 때만 0\~3개 넣습니다. 개수를 채우려고 약한 데이터로 인포그래픽을 만들지 않습니다.

| 카테고리 | 썸네일 | 본문 인포그래픽 |
| --- | --- | --- |
| 변리사의 현장 수첩 | T타입 1개 | 2\~3개 (후보 데이터가 부족하면 1개도 허용) |
| IP 라운지 (특허 전략 노트, AI와 IP, 출원 실무) | T타입 1개 | 1\~2개 |
| IP 뉴스 한 입 | T타입 1개 | 0\~1개 |
| 디딤 다이어리 | 분위기 사진 1장 | 없음 (분위기 사진 최대 1장 추가) |

**인포그래픽 후보가 되는 조건** (하나 이상 충족)

- 비교할 수 있는 숫자 쌍이 있음 (적용 전/후, A안/B안)
- 핵심 수치가 3개 이상
- 3단계 이상의 절차
- 요건·조건이 5개 이상
- 제도·기관 사이의 구조

**배치 규칙**

- 썸네일은 맨 위(제목 바로 아래)에 둡니다.
- 본문 인포그래픽은 그 데이터를 설명하는 문단 바로 뒤에 둡니다. 위치는 문단 ID(`<!-- p:N -->`)로 지정합니다.
- 이미지 두 장을 연속으로 두지 않습니다. 사이에 문단이 최소 2개 있어야 합니다.
- CTA 바로 앞에는 요약형(비교 또는 숫자 카드)을 두는 것을 권장합니다. 단, 데이터가 없으면 생략합니다.

## 규격과 색상

모든 이미지는 폭 1080px로 만듭니다. 네이버 블로그는 모바일에서 많이 읽히므로, 본문 이미지는 세로가 조금 긴 4:5로 해서 글자가 작아지지 않게 합니다.

| 종류 | 비율 | 크기 | 배경 |
| --- | --- | --- | --- |
| 썸네일 (T타입) | 1:1 | 1080×1080px | 카테고리 대표색 단색 |
| 본문 인포그래픽 | 4:5 | 1080×1350px | 흰색 |
| 다이어리 분위기 사진 | 4:3 | 1080×810px | 사진 |

**블로그 이미지 팔레트**

백오피스 화면용 디자인 토큰과는 별도로, 블로그에 나가는 이미지만을 위한 팔레트입니다. 코드에는 이 값을 상수 하나(`BLOG_IMAGE_PALETTE`)로 두고, 프롬프트는 그 상수에서 값을 주입받습니다.

| 카테고리 | 대표색 (썸네일 배경) | 강조색 | 글자색 |
| --- | --- | --- | --- |
| 변리사의 현장 수첩 | 오렌지 #D4740A | 네이비 #1B3A5C | 흰색 #FFFFFF |
| IP 라운지 | 네이비 #1B3A5C | 골드 #C28B2E | 흰색 #FFFFFF |
| IP 뉴스 한 입 | 차콜 #3A3A3A | 레드 #C5302B | 흰색 #FFFFFF |
| 본문 인포그래픽 (공통) | 흰색 배경 | 해당 카테고리 대표색 | 진한 회색 #191F28 |

- 네이비는 기존 썸네일 규칙의 #1A2B4A 대신, 코드의 카테고리 색상과 같은 #1B3A5C로 통일했습니다. 두 색은 눈으로 거의 구분되지 않습니다.
- 한 이미지에 쓰는 색은 배경·글자·강조 3색에 보조 회색 1색까지입니다.
- 기존 규칙의 "감정 톤에 맞춰 색상 자유 선택"은 폐지합니다. 글마다 색이 바뀌면 블로그 전체의 단일한 인상이 사라집니다. 감정 톤은 색이 아니라 헤드라인 문구로 표현합니다.

## 썸네일 (T타입)

썸네일은 네이버 검색결과에서 제목과 함께 보이는 이미지입니다. 도표가 아니라 글자만으로, 작게 줄여도 주제가 읽히게 만듭니다. 다이어리는 이 규칙 대신 분위기 사진을 씁니다.

**레이아웃 (위에서 아래로)**

1. 상단 10\~15%: 작은 카테고리 태그 (예: "현장 수첩") 또는 여백
2. 중앙 60\~70%: 메인 문구
3. 하단 15\~20%: 얇은 구분선 위에 "특허그룹 디딤" (가운데 정렬, 메인 글자의 15\~25% 크기)

**메인 문구**

- 글 제목의 핵심을 2\~3줄로 나누고, 한 줄은 6\~9자 안에서 의미 단위로 끊습니다.
- 문구 폭이 이미지 폭의 80% 이상을 차지합니다.
- 가장 중요한 단어나 숫자 하나만 강조색으로 표시합니다.
- 서브문구는 선택이며, 메인 아래 1줄 12\~18자입니다.
- 제목과 똑같은 문장을 그대로 옮기지 않습니다. "N가지", "완벽 가이드" 같은 제목 공식 대신 독자의 질문이나 상황을 씁니다.

| 제목 | ❌ 기존 방식 | ✅ v2 |
| --- | --- | --- |
| 벤처기업인증 유형 3가지, 잘못 고르면 생기는 5가지 불이익 | 벤처인증 / 유형 3가지 / 총정리 | 벤처인증 / 유형 잘못 고르면 / 생기는 일 |
| 연구인력개발비 세액공제, 2억4천 비용에서 6천만 원 돌려받은 법 | 6천만 원 / 돌려받는 / 방법 | 연구인력 비용 / 얼마나 / 돌려받을까 |

**금지**

- 수치 비교표, 체크리스트, 절차 도식 (본문 인포그래픽으로)
- 10자가 넘는 한 줄
- 결과를 보장하는 표현 (공통 원칙 3)
- 사진·일러스트가 글자 영역을 침범하는 것

## 본문 인포그래픽 유형

유형은 기존 8가지를 그대로 쓰되, 데이터 종류로 고릅니다. 한 글에서 같은 유형은 한 번만 쓰고, 프로세스(B)와 퍼널(F)은 함께 쓰지 않습니다.

| 유형 | 쓸 때 | 필수 데이터 | 레이아웃 (4:5) |
| --- | --- | --- | --- |
| A. 비교 | 적용 전/후, A안/B안 | 비교할 숫자 쌍 1개 이상 | 위아래 2단 또는 좌우 2분할, 가운데 차이 표시 |
| B. 프로세스 | 신청 절차, 업무 흐름 | 3\~5단계 | 위에서 아래로 단계 박스 + 화살표 |
| C. 숫자 카드 | 핵심 수치 요약 | 수치 3\~4개 | 2×2 그리드 또는 세로 3칸 |
| D. 타임라인 | 기한, 개정 연혁 | 날짜·기간 3개 이상 | 세로 축, 시간 순 아래로 |
| E. 체크리스트 | 자격 요건, 준비 서류 | 항목 5\~7개 | 체크 아이콘 + 한 줄 항목 |
| F. 퍼널 | 단계별 탈락·전환 | 단계별 수치 3개 이상 | 위가 넓고 아래가 좁은 단 |
| G. 구조도 | 제도·기관 관계 | 주체 3개 이상과 관계 | 블록 + 연결선, 중심 주체 가운데 |
| H. 수평 막대 | 항목별 금액·비율 | 같은 단위 수치 3\~6개 | 큰 값부터 아래로 정렬 |

**카테고리별 우선 유형**

- 현장 수첩: A(비교) 우선. 절세·인증·연구소 글은 적용 전후 비교가 가장 설득력이 있습니다. 다만 비교할 숫자가 본문에 없으면 만들지 않습니다(기존의 "A 필수"를 "A 우선"으로 완화).
- IP 라운지: G(구조도), D(타임라인), H(수평 막대) 우선.
- 특허·상표 출원 실무: B(프로세스), D(타임라인), E(체크리스트) 우선.
- IP 뉴스 한 입: 쓴다면 C(숫자 카드) 1개만.

**다이어리 예외**

- 인포그래픽 설계 단계를 실행하지 않습니다.
- 분위기 사진 1\~2장만 씁니다. 가능하면 실제 사무실·현장 사진을 쓰고, AI 사진은 사람 얼굴이 나오지 않게 합니다.
- 사진에 글자·로고·CTA를 넣지 않습니다.

## 설계 프롬프트 필수 요소

설계 단계는 이미지 한 장마다 아래 8가지를 JSON으로 냅니다. 기존의 '감정 톤'과 '색상 자유 선택'은 빼고, 대신 이미지에 들어갈 글자를 정확히 적는 `texts` 항목을 넣었습니다.

| 항목 | 내용 |
| --- | --- |
| `type` | T 또는 A\~H |
| `position` | 썸네일은 "top", 나머지는 문단 ID "p:N" |
| `headline` | 20자 이내. 데이터 이름이 아니라 독자가 얻는 메시지. 광고 규정 준수 |
| `texts` | 이미지에 들어갈 모든 글자의 목록 (라벨·수치·주석). 여기 없는 글자는 이미지에 넣지 않음 |
| `data_source` | `texts`의 수치가 본문 어느 문장에서 왔는지 (본문 그대로 인용) |
| `emphasis` | 강조할 항목 1\~2개 (`texts` 안의 값) |
| `footnote` | 출처(법률·기관), 기준일, 단위. 사례 수치면 "개별 상황에 따라 다름" |
| `alt` | 네이버 ALT 텍스트 20\~40자, 핵심 키워드를 앞에 |

- 한국어·영문 이중 프롬프트는 설계 단계에서 쓰지 않습니다. 그림 단계가 이 JSON과 팔레트로 프롬프트를 만듭니다.
- ALT는 기존 "핵심 3개"에서 이미지마다 1개로 바뀝니다. 같은 키워드를 세 번 넘게 반복하지 않습니다.
- 이모지는 쓰지 않습니다. 이미지 모델이 제대로 그리지 못합니다. 아이콘이 필요하면 "문서 아이콘"처럼 말로 적습니다.

**예시 (A. 비교)**

```json
{
  "type": "A",
  "position": "p:7",
  "headline": "같은 이익, 법인세가 달라진 사례",
  "texts": ["적용 전", "법인세 2억 원", "적용 후", "법인세 약 5,000만 원", "약 75% 감소"],
  "data_source": ["법인세 2억 원을 내던 제조업체가 직무발명보상금 제도를 적용한 뒤 약 5,000만 원으로 줄었습니다"],
  "emphasis": ["법인세 약 5,000만 원"],
  "footnote": "매출 80억 원 제조업 사례 · 조세특례제한법 기준 · 개별 상황에 따라 다름",
  "alt": "직무발명보상금 적용 전후 법인세 비교 인포그래픽"
}
```

## 이미지 생성과 검수

이미지 속 한글은 이미지 모델에 맡기지 않고 코드로 그리는 것을 기본으로 합니다. 숫자와 조문이 한 글자라도 틀리면 안 되는 글이기 때문입니다.

| 방식 | 대상 | 방법 |
| --- | --- | --- |
| 코드 렌더링 (기본) | 썸네일, A\~H 전부 | 유형별 HTML/SVG 템플릿에 `texts`와 팔레트를 넣어 PNG로 내보냄 |
| 이미지 모델 (보조) | 다이어리 분위기 사진, 인포그래픽 배경 일러스트 | "글자 없음"으로 생성 후 필요하면 코드로 글자를 위에 합성 |

- 기존 그림 단계의 "NO text in the image"는 **이미지 모델을 쓸 때에만** 남기고, 인포그래픽 자체는 코드 렌더링으로 만듭니다. 이렇게 하면 두 규칙이 더는 부딪치지 않습니다.
- 이미지 모델 크기는 규격 비율에 가장 가까운 것을 고르고, 1080px 폭으로 자릅니다.

**발행 전 검수 체크리스트**

- [ ] 이미지 속 수치가 모두 본문에 같은 표기로 있다
- [ ] 결과를 보장하는 표현이 없다
- [ ] 썸네일 한 줄이 10자를 넘지 않고, 모바일 크기로 줄여도 읽힌다
- [ ] "특허그룹 디딤" 외에 연락처·URL·다른 브랜드가 없다
- [ ] 색이 팔레트 밖에서 나오지 않았다
- [ ] 이미지가 연속으로 붙어 있지 않다
- [ ] 이미지마다 ALT 텍스트가 있다
- [ ] 기관명이 '지식재산처'로 되어 있다
