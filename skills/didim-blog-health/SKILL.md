# 디딤 블로그 글 관리(건강 점검·내부 링크·시리즈·키워드 커버리지)

백오피스 '글 관리' 기능(manage)을 레포·DB 없이 재현한다. 점수·경과일·커버리지는 `scripts/` 의 Python 포팅으로 **반드시 계산**한다(원본과 같은 결과를 내고, 날짜 계산 실수를 막기 위해서). `skills/_DECISIONS.md`(카테고리 정본=네이버 categoryNo, Notion DB 2개)를 따른다.

브랜드·카테고리·CTA 규칙은 **didim-blog-core 스킬을 함께 읽는다.** 코어가 없을 때를 위한 최소 원칙:
- 글을 고칠 때 연락처는 `admin@didimip.com` 만 쓴다. 디딤 다이어리 글에는 CTA 를 넣지 않는다.
- '특허청'은 '지식재산처'로 고친다. 업데이트 문구에도 절세액·인증·등록 결과를 보장하는 표현을 쓰지 않는다.
- 법령 수치를 고칠 때는 추측하지 말고 didim-blog-factcheck 로 확인한다.

## 언제 쓰나
- 발행한 지 오래된 글, 법률·세무 내용이 들어간 글을 점검할 때
- 법·제도 변경 뉴스가 나와 기존 글 영향 범위를 볼 때
- 작성 중인 글에 넣을 내부 링크(2~3개 권장)를 고를 때
- 시리즈 진행률·다음 회차, 키워드 커버리지를 볼 때

## 입력
- 발행 글 목록: Notion "디딤 블로그 콘텐츠"(data source `collection://463bc815-11ab-4290-9d86-22bd1aa9cfed` 우선) 또는 사용자가 붙여넣은 표/JSON. 스크립트는 한글 속성명(제목·상태·카테고리·2차 분류·categoryNo·타깃 키워드·태그·발행일·마지막 업데이트일·건강 상태·조회수(최근)·발행 URL·시리즈·시리즈 회차)을 그대로 받는다. 본문은 페이지 `## 본문` 섹션을 읽어 `본문` 키로 넣는다(법률 키워드 검사에 필요).
- RSS(https://rss.blog.naver.com/didimip.xml)는 제목·링크·날짜 보조용. 막히면 사용자에게 목록을 요청한다.
- 키워드 풀: Notion "디딤 블로그 키워드"(`collection://4e0fae54-aeb3-48dd-b948-b78886a8e859`, 키워드·카테고리·주제 축·매출 가중치·우선순위·커버리지·발행 글)가 정본. 없으면 사용자 목록, 그것도 없으면 `keyword_coverage.py seed`(UPGRADE_SPEC §4.4 시드 19개).
- 시리즈 계획 편수: 사용자에게 받는다(Notion 에 열이 없음).
- 속성 표: `references/notion-fields.md`.

## 절차

### A. 건강 점검
1. `python3 scripts/content_health.py check --contents list.json --now <ISO>`
   - 대상: 상태 S4·S5, 발행일 있는 글(원본은 S4 만 — `--s4-only`).
   - 경과일 = 오늘 − 발행일(단, `마지막 업데이트일`이 더 늦으면 그 날부터).
   - 카테고리별 기준(점검 / 업데이트): 전환형 3개(지원사업·인증과 특허, 출원·심판 실무, 사례) 60 / 90일, 지식재산 경영·디딤 소식 90 / 120일, 디딤 다이어리 120 / 180일, 그 외 90 / 120일. 레거시 글은 합산 카테고리 기준(절세·인증·연구소→지원사업·인증과 특허, 특허·상표 출원 실무→출원·심판 실무, 컨설팅 후기→사례, 특허 전략 노트·AI와 IP→지식재산 경영, IP 뉴스 한 입→디딤 소식).
   - 법률·세무 키워드(세액공제, 연구소, 벤처인증, 직무발명, 특허법, 법인세, 소득세, R&D, 기업부설연구소, 세무조사, 조세특례제한법, 중소기업기본법)가 제목·본문·타깃 키워드에 있고 30일 이상 지났으면 최소 '점검 필요'.
2. 결과를 업데이트 필요 → 점검 필요 → 정상 순으로 보여준다. 요약 문구: "발행 글 N개 중 M개 점검 필요".
3. 대시보드식 짧은 목록이 필요하면 `content_health.py update-needed` (전환형 60일·기타 90일 단일 기준, 오래된 순 5건).
4. 결과의 `notion_updates` 대로 콘텐츠 DB `건강 상태`(정상 / 업데이트 필요 / 법률 변경 확인)를 쓴다. 사용자가 글을 고쳤다고 하면 `마지막 업데이트일`=오늘, `건강 상태`=정상으로 쓴다(원본의 '업데이트 완료' 버튼). 메모 열은 사람 전용이라 쓰지 않는다.
5. 실제 수정 문안이 필요하면 didim-blog-writer·didim-blog-factcheck 로 넘긴다.

### B. 법률 변경 감지
1. 뉴스 제목/요약을 받거나(필요하면 웹 검색) `content_health.py legal-news --contents list.json --news "…"` 실행.
2. 뉴스에 든 법률 키워드와 같은 키워드를 가진 발행 글을 후보로 보여준다(매칭 키워드 많은 순). 키워드 일치는 후보일 뿐이니, 실제 영향 여부는 글 내용을 읽고 판단해 한 줄 근거를 붙이고, 영향이 있다고 판단한 글만 `건강 상태`=법률 변경 확인으로 쓴다.

### C. 내부 링크 추천
1. `python3 scripts/internal_links.py --source-id "<제목 또는 ID>" --contents list.json [--max 5]` (작성 중 글은 `--source s.json`).
2. 점수: 같은 카테고리 +20, 같은 2차 분류 +15, 타깃 키워드 동일 +30 / 아니면 상대 제목에 포함 +25 / 아니면 본문에 포함 +15, 공통 태그 1개당 +10, 상대 조회수 500 초과 +10. 후보는 발행(S4·S5) 글만, 0점 제외, 상위 5개.
3. 상위 2~3개를 권한다(SEO 권장: 내부 링크 2~3개). 각 링크를 넣을 문단과 앵커 문장을 함께 제안한다. URL 은 `발행 URL` 을 쓰고 없으면 "URL 확인 필요"로 표시한다.

### D. 시리즈
1. `python3 scripts/keyword_coverage.py series --series plan.json --contents list.json` (plan.json = `[{"name": "…", "total_planned": 5}]`).
2. 진행률 = 발행(S4·S5) 편수 / 계획 편수 × 100 (반올림). 등록 편수, 회차 목록, 미발행 회차, 다음 회차 번호를 보여준다. 계획 편수가 없으면 사용자에게 묻는다.

### E. 키워드 커버리지
1. `python3 scripts/keyword_coverage.py coverage --contents list.json [--keywords pool.json] --auto-match`
2. 커버 판정: 키워드 DB `커버리지`가 작성됨/재작성 필요이거나 `발행 글` 관계가 있으면 커버, 아니면(`--auto-match`) 발행 글의 타깃 키워드 일치 → 제목 포함 → 태그 일치 순으로 찾아 `notion_keyword_updates`(커버리지=작성됨 + 발행 글 관계 추가)를 제안한다. 연결 글의 건강 상태가 '업데이트 필요'면 커버리지=재작성 필요를 제안한다.
3. 보고: 전체/커버/미커버, 커버리지 %(80% 이상 초록·50% 이상 네이비·그 아래 빨강), 카테고리별 커버 수, 우선순위별 미커버 키워드, 재작성 필요 목록. 미커버를 `매출 가중치` 높은 순 → 우선순위(높음>보통>낮음) 순으로 '다음에 쓸 키워드'(`next_keywords`)로 보여준다(주제 선정 자체는 didim-blog-planner).

## 출력 형식
- 건강 점검: 표(제목 | 카테고리 | 경과일(기준일) | 판정 | 이유) + 요약 한 줄 + 다음 행동(검토/수정/업데이트 완료 기록).
- 법률 변경: 뉴스 키워드 → 영향 후보 글 표(제목 | 일치 키워드 | 판단 근거).
- 내부 링크: 표(순위 | 제목 | 점수 | 이유 | URL) + 삽입 위치 제안.
- 시리즈: "발행 x / 계획 y편 (z%) · 등록 n편 · 다음 k회차".
- 커버리지: 요약 수치 + 카테고리별·우선순위별 표 + 자동 매칭으로 새로 연결된 목록.

## 금지·주의
- 점검 결과만으로 글을 바꾸지 않는다. 수정은 사용자 확인 후 진행한다.
- 법률 키워드 일치를 '법 개정 영향 확정'으로 말하지 않는다.
- Notion 에 새 열·DB 를 만들지 않는다. 메모 열은 쓰지 않는다. 키워드 DB 의 `현재 순위`·`순위 확인일`은 didim-blog-performance 가 쓴다.
- 내부 링크로 미발행 글·삭제된 글을 추천하지 않는다.
- 레거시 카테고리 글도 합산 카테고리로 비교한다(예: '인증 가이드' 옛글 ↔ '지원사업·인증과 특허' 새 글은 같은 카테고리).
