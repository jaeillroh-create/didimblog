# 지원매치 공고를 추천 소스로 받는 입력 슬롯

> 원본 코드에 없는 기능이다. 확정 결정 사항(skills/_DECISIONS.md §2·§3)에 따라 **로테이션 1주차(지원사업·인증과 특허, categoryNo 25)의 우선 소스**로 쓴다.
> 1차 필터는 `scripts/recommend.py`(`filter_grants`, `grant-check`)가 하고, 제목 다듬기·사실 확인은 Claude 가 한다.

## 1. 입력 슬롯 `grant_items[]` (선택)

지원매치 일일 리포트(정부·지자체 지원사업 공고 요약)를 사용자가 붙여넣거나, 지원사업 검색 커넥터가 있으면 그 결과를 쓴다.

| 필드 | 필수 | 예 |
|---|---|---|
| title | 필수 | 2026년 하반기 IP 나래 프로그램 참여기업 모집 |
| agency | 선택 | 한국발명진흥회 |
| deadline | 권장 | 2026-10-20 |
| url | 권장 | 공고 원문 링크 |
| eligibility | 권장 | 신청 자격 원문 |
| bonus | 권장 | 가점·우대 조건 원문 |
| support | 선택 | 지원 내용 |

## 2. 주제화 규칙

1. **특허·인증이 요건이거나 가점일 때만** 후보로 삼는다. `eligibility` 또는 `bonus` 원문에 다음 중 하나가 있어야 한다(스크립트 판정):
   특허, 실용신안, 디자인권, 상표, 지식재산, IP(영문 단어 단위), 직무발명, 기업부설연구소, 연구전담부서, 벤처기업, 벤처인증, 벤처확인, 이노비즈, 메인비즈, 기술평가, 우선심사.
   제목에만 있고 자격·가점에 없으면 제외한다. 자격·가점 원문이 비어 있으면 원문을 열어 채운 뒤 다시 판정한다.
2. 자격에 있으면 `요건`, 가점에만 있으면 `가점` 으로 표시한다.
3. 마감이 지났으면 버리고, 7일 이내면 URGENT, 그 외 PRIMARY. 마감 가까운 순으로 정렬한다.
4. 카테고리는 **지원사업·인증과 특허(25)**. 1주차에는 메인 후보 2건을 공고로 먼저 채우고, 다른 주에는 25 대안 칸에 1건을 넣는다. 공고 소식만 짧게 알리는 글이 필요하면 사용자 확인 후 디딤 소식(28)으로 쓴다. 디딤 다이어리로는 만들지 않는다.
5. 스크립트 제목은 `(가제) 지원사업 {요건|가점}이 되는 {용어} — '{공고명 앞 30자}' 대비 포인트` 형식이다. Claude 가 브리핑에서 "요건/가점을 갖추는 방법" 관점으로 다듬는다(공고명을 그대로 제목으로 쓰지 않는다).
6. Notion `추천 소스` = `지원매치 리포트`, 메모에 `근거: 공고 URL`.
7. 선정·합격을 보장하는 표현을 쓰지 않는다. 금액·마감·자격은 공고 원문으로 확인하고, 못 했으면 "공고 원문 확인 필요"를 붙인다. 공고 기관이 특허청이면 본문 설명에서는 지식재산처로 쓴다.
