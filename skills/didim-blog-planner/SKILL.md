# 디딤 블로그 주제 추천·주간 기획

백오피스 대시보드의 "이번 주 추천" 위젯과 뉴스 피드, AI 초안 다이얼로그의 브리핑 생성을 레포·DB 없이 재현한다.
결정적인 계산(통계·필터·로테이션·샘플링)은 `scripts/recommend.py` 가 원본 TS 와 같은 결과로 하고, 검색·관련성 판단·브리핑 작성은 Claude 가 원문 프롬프트를 따라 직접 한다.

## 함께 읽기
- 브랜드·카테고리·CTA·명칭 규칙의 정본은 **didim-blog-core** 스킬이다. 설치돼 있으면 함께 읽는다.
- 코어가 없을 때도 지킬 절대원칙(이 스킬에 직접 걸리는 것):
  1. 연락 이메일은 **admin@didimip.com** 하나뿐이다. 브리핑·제목안에 다른 주소를 쓰지 않는다.
  2. **디딤 다이어리에는 CTA 를 넣지 않는다.** 다이어리 브리핑에 CTA·상담 유도 문구를 적지 않는다.
  3. 카테고리·2차 분류 문자열은 **네이버와 100% 일치**시킨다(`변리사의 현장 수첩`, `IP 라운지`, `디딤 다이어리` / 2차는 아래 표). 약칭 `현장 수첩` 을 출력에 쓰지 않는다.
  4. 기관명 `특허청` 은 `지식재산처` 로 쓴다(뉴스 원문 인용 제목은 그대로 두되 브리핑 본문 설명은 바꾼다).
  5. "100% 승인", "반드시 절세", "합격 보장" 같은 결과 보장 표현을 제목안에 쓰지 않는다.

## 언제 쓰나
- 주간 루틴 시작(주말 음성 브리핑 전, 월요일 초안 전)에 이번 주 주제를 정할 때.
- 추천이 마음에 안 들어 새로고침하거나 특정 추천을 부적합 처리할 때.
- IP·세제·인증 관련 최신 뉴스로 긴급 글감을 찾을 때.
- 정한 주제를 writer 스킬에 넘길 브리핑(카테고리·키워드·타깃·에피소드·참고사항)으로 정리할 때.

## 입력
| 입력 | 필수 | 얻는 법 |
|---|---|---|
| 발행 이력(날짜, 카테고리, 2차분류, 키워드, 제목) | 필수 | ① Notion DB "디딤 블로그 콘텐츠"(상태 S4) ② `scripts/fetch_rss_history.py` ③ 사용자 붙여넣기 |
| 부적합 이력 30일 / 최근 48시간 노출 | 선택 | Notion `추천 상태` 필드 또는 이 대화의 기록 |
| 뉴스 | 선택 | 웹 검색 도구(§4) |
| 키워드 풀(우선순위), 조회수·상담 수, 직접 주제, 지원사업 공고 | 선택 | 사용자 제공 |
| 오늘 날짜, 블로그 시작일(기본 2026-01-06) | 권장 | 대화 맥락 |

입력 JSON 형식과 Notion 필드 매핑은 `references/history-input.md`.

## 카테고리 구조 (추천 엔진 기준)
| 1차 | 월 목표 | 2차 분류(이름이 정본) | 카드 수 |
|---|---|---|---|
| 변리사의 현장 수첩 (CAT-A) | 2 | 절세 시뮬레이션 / 인증 가이드 / 연구소 운영 실무 / 특허·상표 출원 실무 | 2 |
| IP 라운지 (CAT-B) | 1 | 특허 전략 노트 / AI와 IP / IP 뉴스 한 입 | 2 |
| 디딤 다이어리 (CAT-C) | 1 | 컨설팅 후기 / 디딤 일상 / 대표의 생각 | 1 |

주의: CAT-B-01/02 ID 가 코드 안에서 서로 반대로 정의돼 있다(`references/recommendation-rules.md` §6). 다른 스킬로 넘길 때 **2차 분류 이름**을 반드시 함께 적는다.

## 절차

### 1. 발행 이력 모으기
1. Notion 커넥터가 있으면 "디딤 블로그 콘텐츠" DB 를 찾아 S4 행을 읽는다. DB 가 없으면 만들지 않는다.
2. 없으면 `python3 scripts/fetch_rss_history.py > history.json` 을 실행한다.
   - `unknown_sub_categories` 가 나오면(예: `지식재산 경영`) 어느 1차 카테고리인지 사용자에게 묻고 `--map` 으로 다시 실행한다. 묻기 전까지 그 글은 통계에서 빠진다고 알린다.
   - 실패(네트워크 차단)하면 사용자에게 최근 글 목록을 붙여넣어 달라고 한다.
3. 부적합·노출 기록이 있으면 `rejected`, `recently_shown` 에 넣는다.

### 2. 뉴스 확인 (IP 라운지 뉴스 카드·긴급 감지)
§4 절차로 검색하고, 관련성 판단을 통과한 기사만 `news_items` 에 넣는다. 웹 검색 도구가 없거나 사용자가 생략을 원하면 건너뛴다(원본도 뉴스 실패 시 나머지 추천을 계속한다).

### 3. 추천 계산
```bash
python3 scripts/recommend.py plan input.json --format md      # 표
python3 scripts/recommend.py plan input.json > result.json     # 전체 JSON
```
스크립트가 하는 일(원본 규칙):
1. 이번 달(1일 이후) 발행 수를 1차 카테고리별로 센다 → 2:1:1 목표 대비 부족분이 큰 카테고리를 **이번 주 필요 카테고리**로 정한다. 모두 채웠으면 현장 수첩(매출 직결).
2. 부족분 1위가 직전 발행 글과 같은 카테고리면 차순위를 고른다(연속 방지). 그래도 같으면 `warnings` 로 경고한다.
3. 필터: 30일 안 부적합 키워드와 3회 이상 부적합 키워드는 **절대 노출 금지(hard)**, 48시간 안 노출·지금 보이는 추천·이미 발행한 키워드는 **가능하면 회피(soft — 대안이 없으면 허용)**.
4. 카테고리별 카드: 현장 수첩 = 2차 분류를 섞어 돌리며 키워드 2개(같은 2차 분류 반복 회피) → 모자라면 12주 스케줄. IP 라운지 = 최근 7일 뉴스(URGENT) → 2차 분류 키워드 → 스케줄. 다이어리 = 주제 풀 → 스케줄.
5. 선택 소스: 키워드 풀(HIGH 50/MEDIUM 30/LOW 20 확률), 성과 후속편(조회수 + 상담×500), 직접 주제.
6. 표 우선순위: 뉴스 = URGENT, 필요 카테고리 카드 = PRIMARY, 나머지 = SECONDARY. 필요 카테고리 첫 카드에 "(메인)".

`warnings` 는 그대로 사용자에게 보여 준다. 12주 스케줄은 W1~W12 뿐이라 13주차 이후에는 카테고리 전체 스케줄에서 고른다는 점(`schedule_in_range: false`)도 알린다.

### 4. 뉴스 검색 (원본 API → 웹 검색 도구로 대체)
1. 검색어: 결과 JSON 의 `news_search_plan` — 긴급 키워드 3개(`특허법 개정`, `직무발명 판례`, `AI 기본법`, `세액공제 변경`, `벤처인증 요건` 중 무작위), 고정 수집 키워드 10개, 2차 분류별 뉴스 키워드. 전부 할 필요는 없고 긴급 3개 + 사용자 관심 2차 분류 키워드를 우선한다.
2. 각 검색어로 최근 7일 기사(최신순, 검색어당 5건 안팎)를 모아 `{title, description, link, pubDate, keyword}` 로 정리한다.
3. `python3 scripts/recommend.py news-check articles.json` → 칼럼·인터뷰·광고 등 비뉴스와 7일 초과·중복 링크를 빼고 규칙 점수를 붙인다.
4. 남은 `candidates` 에 대해 Claude 가 `references/news-and-briefing.md` §4 의 "디딤 블로그 편집자" 관련성 판단 프롬프트를 그대로 따라 글감 여부를 정한다. 통과한 기사마다 §5 프롬프트대로 3줄 요약(`ai_summary`)과 블로그 각도(`blog_angle`)를 만든다.
5. **긴급 발행 감지**: `urgent_candidates`(3일 이내 + 규칙 점수 10 이상) 중 관련성 판단도 통과한 기사가 있으면 표 맨 위에 URGENT 로 올리고, 관련 기존 글(이력 제목·키워드에 그 검색어가 들어간 글, 최대 5개)을 함께 보여 준다.
6. 주제에 쓸 기사는 원문 링크를 열어 사실을 확인한다. 확인 못 한 숫자·날짜는 "확인 필요"로 표시한다.
7. 사용자가 특정 키워드 조사를 원하면 §2 키워드 확장(3~5개)·§3 검색 결과 요약 형식을 따른다.

### 5. 표 보여 주기와 피드백
- 표를 보여 준 뒤 "적합(초안으로)", "부적합", "새로고침" 중 고르게 한다.
- **부적합**: 사유를 고르게 한다(주제가 디딤 서비스와 관련 없음 / 이미 다룬 주제 / 시의성 없음 / 기타). `scripts/recommend.py reject-keywords --title … --keywords …` 결과를 저장한다. 추출 키워드에 `2026년` 같은 연도 토큰이 섞이면(원본 동작) 이후 같은 연도가 들어간 뉴스·스케줄 제목이 모두 막히므로 저장 전에 사용자에게 빼도 될지 묻는다.
- **새로고침(전체/카테고리별)**: 지금 보이는 제목을 `exclude` 에, 해당 카테고리 첫 카드의 2차 분류를 `preferred_sub` 에 넣고 다른 `--seed` 로 다시 돌린다.
- **적합**: §6 브리핑으로 넘어간다. Notion 이 있으면 `추천 상태=적합`, 상태 S0 으로 기록한다.

### 6. writer 로 넘길 브리핑
`references/news-and-briefing.md` §6 의 브리핑 프롬프트를 Claude 가 직접 따라 작성한다(user: `주제: <제목안>`). 카테고리를 표에서 이미 정했으면 "카테고리는 반드시 …를 사용하세요" 조건을 지킨다.
- categoryId 는 `CAT-A | CAT-B | CAT-B-03 | CAT-C` 중 하나, 아니면 CAT-A 로 되돌린다. secondaryCategoryId 가 목록 밖이면 비운다(원본 검증).
- `episode`(실제 사례)는 지어내지 않는다. 사용자가 준 사례가 없으면 "대표 음성 브리핑에서 받을 것"이라고 비워 둔다.
- 뉴스 기반이면 `additionalContext` 에 `참고 자료(뉴스 원문): <URL>` 을 넣는다(원본 초안 다이얼로그 동작).
- 스케줄 기반이면 seed_data 의 `target`·`legal_basis` 를 참고사항에 넣는다(`references/schedule-12weeks.md`).

## 출력 형식
```
**월간 발행 현황**: 변리사의 현장 수첩 0/2 · IP 라운지 1/1 · 디딤 다이어리 0/1
**이번 주 필요 카테고리**: 변리사의 현장 수첩 (W39, 12주 스케줄 범위 밖)
> 주의: (warnings)

| # | 우선순위 | 카테고리 | 2차분류 | 제목안 | 타깃 키워드 | 근거 소스 |
|---|---|---|---|---|---|---|
| 1 | URGENT | IP 라운지 | IP 뉴스 한 입 | … | … | 뉴스 [URL] — 블로그 각도 |
| 2 | PRIMARY (메인) | 변리사의 현장 수첩 | 연구소 운영 실무 | … | … | 키워드 풀 — … |
```
제목안이 템플릿(`… 완벽 가이드 (2026년 최신)` 등) 그대로면 "가제"라고 표시하고, 원하면 브리핑 단계에서 다듬는다.

선택한 주제마다 writer 로 넘길 블록:
```
[브리핑 → didim-blog-writer]
- 카테고리: 변리사의 현장 수첩 (CAT-A)
- 2차 분류: 연구소 운영 실무 (CAT-A-03)
- 주제: …
- 핵심 키워드: …
- 타깃 독자: …
- 에피소드: … (없으면 "대표 음성 브리핑에서 받을 것")
- 참고사항: 관련 법 조항·주의점 / 참고 자료(뉴스 원문): URL
- 추천 근거: 소스·우선순위·사유
```

## 금지·주의
- 추천 수치(월간 현황, 부족분)를 손으로 계산하지 말고 스크립트 결과를 쓴다. 스크립트를 못 돌리는 환경이면 `references/recommendation-rules.md` 규칙대로 계산하고 그렇게 했다고 밝힌다.
- 뉴스 기사 내용·숫자를 지어내지 않는다. 링크 없는 뉴스 카드는 만들지 않는다.
- 다이어리 주제에 서비스 홍보·상담 유도를 붙이지 않는다.
- Notion DB 를 새로 만들거나 네이버에 자동 발행하지 않는다.
- 지원사업 공고(`grant_items`)는 신규 초안 기능이다 → `references/grant-source-draft.md` 규칙(특허·인증이 요건/가점인 공고만)대로 Claude 가 직접 판단한다.
