# 네이버 발행 준비 (didim-blog-publish-prep)

백오피스의 "네이버 발행 준비" 화면(src/app/(dashboard)/contents/[id]/publish)과 src/lib/utils/publish-helpers.ts 를 옮긴 스킬이다.
네이버 에디터는 마크다운을 지원하지 않으므로, 붙여넣기 전에 기호를 걷어내고 CTA·태그·ALT 를 따로 준비한다.
브랜드·카테고리·CTA 원문은 **didim-blog-core 스킬을 함께 읽는다.** 코어가 없어도 아래 핵심 원칙은 지킨다.

## 핵심 원칙 (코어 미설치 대비)
- 모든 이메일은 **admin@didimip.com** 으로 바꾼다(CTA 는 출력 전 강제 치환). 전화 02-571-6613.
- **디딤 다이어리(categoryNo 17·18~20)와 디딤 소식의 사무소 소식에는 CTA를 넣지 않는다.** 다이어리는 대신 "디딤 다이어리는 CTA를 넣지 않습니다. 상업적 CTA가 진정성을 훼손할 수 있습니다." 안내만 한다.
- 현재 시점 '특허청'은 '지식재산처'(2025-10-01). 발행 화면은 이를 자동으로 고치지 않으므로 본문에 남아 있으면 경고한다.
- 결과 보장·단정 표현("반드시 절세됩니다")이 보이면 발행 전에 경고한다(광고 규정).
- 자동 발행 기능은 만들지 않는다. 사용자가 복사·붙여넣기로 발행한다.

## 입력
| 항목 | 필수 | 설명 |
|---|---|---|
| title | ✓ | 글 제목 |
| body | ✓ | 마크다운 본문(초안 그대로. `## 소제목`, `**볼드**`, `[IMAGE: …]`, `━━ 📷 이미지 N ━━` 블록 포함 가능) |
| category | ✓ | 네이버 카테고리 이름 또는 categoryNo (예: "지원사업·인증과 특허", 27, "특허 전략 노트"). 정본은 네이버 categoryNo, 코어 categories.md A절 |
| office_news | | 디딤 소식(28) 중 사무소 소식이면 true → CTA 없음 |
| category_id / secondary_category | | (레거시 호환) 백오피스 CAT-* ID. category 가 없을 때만 쓰며 원본 화면과 똑같이 계산 |
| target_keyword | | 타깃 키워드(CTA 1순위 매칭에 쓰임) |
| tags | | 태그 배열. 없으면 3단계에서 생성 |
| status | | S0~S5. S3 미만이면 "미리보기 모드" |
| is_ai_generated | | AI 도움 여부(기본 true → 면책에 AI 고지 포함) |
| publish_date | | 발행예정일 |
| cta_override_key / disclaimer_override | | 사용자가 CTA·면책 레벨을 직접 고를 때 |

가져오는 순서: 사용자가 붙여넣은 내용 → Notion 커넥터가 있으면 "디딤 블로그 콘텐츠" DB(data source `collection://463bc815-11ab-4290-9d86-22bd1aa9cfed`)의 해당 글 — 속성: 제목·상태·카테고리·레거시 2차 분류·categoryNo·타깃 키워드·발행일, 페이지 본문: 초안·태그 줄·AI 도움 여부 → 없으면 사용자에게 묻는다. 레거시 글(`카테고리 = 레거시`)은 `레거시 2차 분류` 이름을 category 로 쓴다.

## 절차
1. **입력 확인**: 제목·본문·카테고리가 없으면 묻는다. 카테고리는 네이버 이름/categoryNo 로 받는다. 레거시 카테고리(변리사의 현장 수첩·IP 라운지 하위)는 사용자가 지정한 경우에만 쓰고, 출력에 신규 대응 카테고리를 함께 알린다. CAT-B-01/02 처럼 CAT ID 만 있으면 이름을 다시 확인한다.
2. **JSON 작성**: 위 항목으로 `content.json` 을 만든다(`scripts/example_content.json` 참고).
3. **태그가 없을 때**: `python3 scripts/publish_prep.py auto-tags` (입력 {category, target_keyword, keyword_positions}) 로 10개를 만들고 사용자에게 보여 준 뒤 tags 에 넣는다. 다이어리는 브랜드 태그 2개(특허그룹디딤, 디딤변리사)만 나온다.
4. **블록 생성**: `python3 scripts/publish_prep.py build -i content.json --format text` 로 붙여넣기용 블록을, `--format json` 으로 세부 값(body_html, 칩 상태 등)을 얻는다. Python 을 쓸 수 없으면 `references/publish-helpers.md` 1절 순서를 손으로 그대로 적용한다.
5. **결과 점검** — 아래 중 해당하는 것을 블록 위에 "⚠️ 확인 필요"로 짧게 적는다.
   - `extra.body_has_cta` 가 true 이고 CTA 블록도 있음 → 본문 끝에 이미 CTA(━━ 또는 admin@didimip)가 있다. 둘 중 하나만 쓰라고 안내한다.
   - 본문에 `| … |` 표 줄이 남음 → 표 데이터 블록을 에디터 표에 붙여넣고 본문의 표 줄은 지우라고 안내.
   - 코드 블록 잔재(`` ` `` 로 시작하는 줄), 줄 전체 `***` 가 `• ` 로 바뀐 줄 → 수동 정리 안내.
   - 이미지 가이드가 비었는데 `extra.image_blocks` 가 있음 → 여러 줄 이미지 블록을 번호별로 안내하고 ALT 후보를 제시.
   - 태그 칩 중 `overflow`/`excluded` → 100자 초과로 빠진 태그를 알린다.
   - 본문에 '특허청'(현재 시점), admin@didimip.com 외 이메일, 결과 단정 표현 → 경고(코어의 `core_rules.py check`/`replace-names` 가 있으면 실행).
   - 다이어리인데 본문에 상담·문의·연락·무료·진단·시뮬레이션·admin@ → 삭제 권고.
6. **출력**: 아래 "출력 형식" 그대로 내놓는다.
7. **발행 후**: 사용자가 체크리스트 7개를 모두 마쳤다고 하면, 상태가 S3(발행예정)일 때만 "발행 완료(S3→S4)"를 진행한다. Notion "디딤 블로그 콘텐츠"에 사용자 확인 후 `상태 = S4 발행완료`, `발행일`, `발행 URL`(네이버 글 주소), `categoryNo`·`카테고리`를 기록한다(선택지 문자열은 코어 notion-storage.md 그대로). 커넥터가 없으면 이 값들을 표로 출력해 붙여넣기를 요청한다. 상태 전이 조건 검증은 didim-blog-ops 스킬이 맡는다.

## 출력 형식 — 네이버 에디터에 그대로 붙여넣을 블록
블록 순서 = 에디터에 붙여넣는 순서다. 각 블록은 4개 백틱 코드 블록(````text) 하나로, 안의 내용만 그대로 복사하면 되게 만든다. 코드 블록 밖에는 한 줄 안내만 둔다.

```
(S3 미만이면) ⚠️ 미리보기 모드 — 현재 상태가 {상태}이므로 … 발행 완료 처리는 S3(발행예정) 이상에서 활성화됩니다.
(점검 결과가 있으면) ⚠️ 확인 필요: …
카테고리: {이름} (categoryNo N, new/legacy/diary) · 프롬프트 키 …

## [1] 제목 → 네이버 '제목' 칸 (N자)
## [2] 본문 → 본문 영역에 붙여넣기 (N자)        ← stripMarkdown 결과
## [2-1] 표 데이터 (N개) → 에디터에서 표 삽입 후 붙여넣기   ← 표가 있을 때만
## [3] 면책조항 Level X — 라벨 (자동: Y)        ← 다이어리·none 이면 생략. CTA 구분선 바로 앞에 둔다
## [4] CTA (categoryName) — 매칭: 근거           ← 다이어리면 "CTA 없음" + 안내문
## [5] 태그 → 태그 입력란 (N/100자 · M개)
## [6] 이미지 가이드 / ALT                        ← #순번 설명 + ALT, 마지막에 ALT 전체 블록
## [7] 포맷 가이드 (참고용, 복사 안 함)
## [7-1] 서식 행 가이드 (참고용)                   ← "N행 … → 네이버 제목2", "━━━ → 구분선", "이미지 N 삽입"
## [8] 발행 체크리스트 (7항목)
## 콘텐츠 정보: 카테고리 · 타깃 키워드 · 발행예정일 · 본문 글자수
```

발행 체크리스트 7개(원문, 순서 고정): ☐ 제목 복사 완료 / ☐ 본문 복사 & 붙여넣기 완료 / ☐ 이미지 삽입 완료 (ALT 텍스트 포함) / ☐ CTA 복사 & 배치 완료 / ☐ 태그 10개 입력 완료 / ☐ 네이버 에디터 포맷 적용 완료 / ☐ 미리보기 확인 완료.
기획서(UPGRADE_SPEC §8.1)의 확인 포인트 "소제목에 '제목2' 서식", "화요일 09:00 예약 발행 설정", "PC + 모바일 미리보기"는 해당 항목 옆 괄호로 덧붙여도 된다.

사용자가 서식(볼드·제목 색)까지 원하면 JSON 의 `body_html` 을 HTML 파일로 저장해 브라우저에서 열고 복사하도록 안내한다(원본의 "서식 포함 복사"). 기본은 순수 텍스트다.

## 규칙 요약 (자세한 원문은 references)
- **본문 변환**(stripMarkdown): 제목 기호·볼드·이탤릭·취소선·인라인 코드·코드 블록·링크 기호 제거, `---` → ━ 18개, 글머리 → `• `, `1.` → `1 `, `>` 제거, 빈 줄 3개+ → 2개. 이미지 마커는 남긴다.
- **태그**: 공백·# 제거 → `#태그` 를 공백으로 연결, 100자를 넘기 직전에서 멈춘다.
- **CTA (신규 구조, _DECISIONS.md 2절)**: 25 지원사업·인증과 특허 → 타깃 키워드(없으면 제목)로 절세/인증/연구소 템플릿, 불일치 시 인증 진단 · 27 출원·심판 실무 → 출원 CTA · 26 사례 → 키워드 정규식 7개 전체 매칭, 불일치 시 출원 · 24 지식재산 경영 → 이웃 추가 CTA · 28 디딤 소식 → 가벼운 이웃 추가(사무소 소식은 없음) · 17 다이어리 → 없음 · 7/22 고정 페이지 → 대상 아님. 마지막에 이메일 강제 치환. 표: `references/publish-screen.md` 3-1절.
- **CTA (레거시 카테고리·CAT-* 입력)**: 백오피스 원본 그대로 — 다이어리면 없음 → 1순위 타깃 키워드 정규식(절세 → 출원 → 인증 → 연구소 → AI → 전략 → 뉴스) → 2순위 2차 분류 → 3순위 1차 이름 앞 4글자 → 4순위 1차 ID 범용 → 5순위 첫 템플릿. `references/publish-screen.md` 3절.
- **면책**: 카테고리의 CAT 별칭으로 원본 규칙 적용 — 다이어리 → 없음, 절세 매칭(25)·절세 시뮬레이션 또는 절세 키워드+금액 → A, 디딤 소식·IP 뉴스 한 입 → C, 나머지 → B.
- **포맷 가이드**: CAT 별칭으로 5종 고정 문구 중 선택(25·26·27 → 현장 수첩용, 24 → IP 라운지용, 28 → IP 뉴스 한 입용, 17 → 다이어리용). 문구 머리의 레거시 카테고리 이름은 원문이므로 그대로 둔다.
- **ALT**: [IMAGE: 설명] 의 설명 그대로. 새로 쓸 때는 `references/image-alt-rules.md` 의 ALT_TEXT_RULES(핵심 키워드 앞, 20~40자).

## 금지·주의
- 블록 안 문구(CTA·면책·포맷 가이드·체크리스트)를 고쳐 쓰지 않는다. 원문 그대로 낸다.
- 다이어리·사무소 소식에 CTA·연락처·이메일을 붙이지 않는다. 체크리스트의 'CTA 복사 & 배치'는 CTA 가 없는 글이면 "해당 없음"으로 표시한다.
- CTA 를 본문과 CTA 블록에 두 번 넣지 않는다.
- 상태가 S3 미만이면 "발행 완료" 처리를 하지 않는다(복사·확인만).
- 네이버에 자동으로 올리거나 예약하지 않는다.

## 스크립트
`scripts/publish_prep.py` — publish-helpers.ts 전체 + 화면 로직(CTA 매칭·면책·체크리스트·태그 칩) + generateAutoTags 포팅. Python 3 표준 라이브러리, JSON 입출력, `--help` 지원. 원본 TS 를 node 로 실행한 결과와 12개 입력(+ CTA·체크리스트 상수)에서 결과가 완전히 같음을 확인했다.
하위 명령: `build`, `strip-markdown`, `to-html`, `tables`, `tags`, `format-guide`, `enforce-email`, `image-guide`, `disclaimer`, `match-cta`(레거시·원본), `match-cta-new`(신규 구조), `resolve-category`, `auto-tags`, `line-guide`(스킬 추가).
예: `python3 scripts/publish_prep.py strip-markdown --raw -i draft.md`
