# 디딤 블로그 SEO 점수·체크리스트

원본 백오피스의 SEO 자동 점수 패널(seo-calculator), 18항목 체크리스트(레거시 판정), 품질 점수 계산을 옮긴 스킬이다.
점수는 **반드시 스크립트로 계산**한다. 사람이 눈으로 세면 원본 규칙(공백 제외 글자수, 대소문자 무시 키워드 수, 부분 점수 구간)과 어긋나기 쉽다.

브랜드·카테고리 공통 규칙은 **didim-blog-core 스킬을 함께 읽는다.** 코어가 없어도 다음은 지킨다.
- 디딤 다이어리(17)와 디딤 소식의 '사무소 소식'은 CTA 가 **없어야** 점수를 받는다. CTA 추가를 제안하지 않는다.
- CTA 연락처 이메일은 admin@didimip.com 이다(CTA 감지 패턴 중 하나).
- 점수를 올리려고 결과 보장 표현이나 키워드 과다 반복을 권하지 않는다(키워드는 상한도 있다).
- 현재 시점 기관명은 '특허청'이 아니라 '지식재산처'다(제목·태그 제안 시).

## 언제 쓰나
- 초안·수정본의 SEO 점수와 개선 힌트가 필요할 때 (원본: 콘텐츠 상세 우측 "SEO 점수" 패널, 저장 시 seo_score 저장).
- 발행 전 18항목 체크리스트를 확인할 때 (원본: 레거시 SeoChecklist / 상태 전이 체크 "SEO 점수 70점 이상(권장)").
- 발행 후 성과 수치로 품질 점수·등급을 낼 때.

## 입력
| 항목 | 필요 | 없을 때 |
|---|---|---|
| 제목, 본문(마크다운) | 필수 | 사용자에게 요청 / Notion "디딤 블로그 콘텐츠" DB 의 제목 + 해당 글 페이지 본문. 카테고리·categoryNo·타깃 키워드·상태도 같은 행에서 읽는다(상태 "S1 초안완료", 카테고리 "레거시" + `legacy_subcategory`(레거시 2차 분류) 그대로 넣어도 된다) |
| 타겟 키워드 | 강력 권장 | 없으면 키워드 항목 0점("타겟 키워드를 설정하세요") — 사용자에게 묻는다 |
| 태그 목록 | 권장 | 없으면 태그 0개로 채점됨 — 태그를 받거나 "태그 미입력"을 명시 |
| 카테고리 (네이버 이름 또는 categoryNo, 레거시 이름·CAT-* 도 가능) | 권장 | CAT-A(현장 수첩) 루브릭으로 계산됨 — 지식재산 경영·디딤 소식·다이어리면 반드시 받는다 |
| 세부 유형 | 디딤 소식만 | "사무소 소식"이면 `subtype` 으로 넣는다(CTA 부재 가점) |
| 상태 S0~S5 | 권장 | 묻는다. 답이 없으면 S2(전체 7항목, 발행 불가 판정 없음)로 계산하고 그렇게 했다고 밝힌다 |
| 예약 발행 시각 | 선택 | 18항목 중 18번만 사람 확인으로 남는다 |

카테고리 → 루브릭 (정본 = 네이버 categoryNo, _DECISIONS.md 2026-10-01). 원본 루브릭 4종을 그대로 쓰고 매핑만 추가했다.

| 카테고리 (categoryNo) | 루브릭 |
|---|---|
| 지원사업·인증과 특허 (25), 출원·심판 실무 (27), 사례 (26) | 현장 수첩 CAT-A |
| 지식재산 경영 (24) | IP 라운지 일반 CAT-B |
| 디딤 소식 (28) | IP 뉴스 한 입 CAT-B-03 |
| 디딤 소식 > 사무소 소식 | CAT-B-03 수치 + CTA 없으면 +10 (다이어리식) |
| 디딤 다이어리 (17; 18 컨설팅 후기, 19 디딤 일상, 20 대표의 생각) | 다이어리 CAT-C |
| 레거시: 변리사의 현장 수첩 (9; 10·11·12·23) / IP 라운지 (13; 14·15) / IP 뉴스 한 입 (16) | CAT-A / CAT-B / CAT-B-03 |
| 디딤 소개 (7), 상담 안내 (22) | 고정 페이지 — 채점 대상 아님(계산 시 CAT-A, 경고 표시) |

입력은 이름(`"category": "출원·심판 실무"`), 번호(`"category_no": 27`), 레거시 CAT-* ID(`category_id`/`secondary_category`, 원본 getRubric 규칙) 모두 받는다. 결과의 `categoryInfo` 로 어떻게 해석했는지 확인하고 보고에 적는다.

## 절차
1. **입력 정리** — 위 표대로 값을 모은다. 카테고리 이름만 들으면 ID 로 바꾼다.
2. **자동 점수** — `scripts/seo_score.py` 에 `{title, body, target_keyword, tags, status, category 또는 category_no (또는 레거시 category_id/secondary_category), subtype}` JSON 을 넣는다(본문이 길면 `--body-file`). 결과: 항목별 점수/만점/실측/기준/힌트, normalizedScore, verdict, 색상.
3. **18항목 체크** — `scripts/seo_checklist.py` 에 같은 입력(+`scheduled_at`)을 넣는다. 자동 판정 항목은 근거(basis)와 함께, 판정 불가 항목은 `pending_human` 으로 나온다.
4. **정성 항목 판단** — pending 항목 중 텍스트로 판단할 수 있는 것은 Claude 가 읽고 의견을 낸다: 4 도입부 톤(사람의 상황으로 시작하는지), 7 소제목 키워드 변형, 15 태그 구성(핵심3+연관3+브랜드2+롱테일2), 17 맞춤법(오탈자 지적만, 통과 판정은 네이버 검사기). 9 첫 이미지·10 ALT·12 내부 링크·18 예약 시간은 사용자 확인으로 남긴다. 사용자가 확인해 주면 `manual` 로 넣어 다시 실행해 판정을 갱신한다.
5. **보고** — 출력 형식대로. 힌트는 원본 문구를 그대로 쓴다.
6. **(선택) 간이 점수** — AI 에디터에서 저장되던 8항목 간이 점수가 필요하면 `scripts/seo_editor_check.py`. 정식 점수와 기준이 다르다(대소문자 구분, `###` 미포함, 태그 8개, 카테고리 무시).
7. **(선택) 품질 점수** — 발행 글의 조회수·평균 체류시간(초)·CTA 클릭 수를 받아 `scripts/quality_score.py`. 한 달치 글 목록을 주면 월 최댓값으로 정규화한다. 등급: 80↑ 우수(excellent), 60↑ 양호, 40↑ 보통, 20↑ 부진, 그 외 위험.

## 핵심 규칙 (원문은 references)
- 상태별 범위: S0 제목만 → S1 +본문·키워드·소제목·CTA → S2~S5 +이미지·태그.
- 부분 점수: 범위 안 만점, `tol1=max(ceil(폭×1.6),5)` 안 67%, `tol2=max(ceil(폭×2.2),10)` 안 33%, 밖 0 (반올림).
- 판정: 80↑ 통과, 80 미만 수정 필요, **S3·S4·S5 에서 50 미만이면 발행 불가**. 색: 80↑ 초록, 50~79 주황, 0~49 빨강.
- 다이어리: 소제목 항목 제외(배점 0), CTA 없으면 +10, 있으면 0. 사무소 소식도 CTA 는 같은 규칙.
- 이미지 마커: `seo_score.py` 는 기본으로 박스형 다중 줄 마커(`[IMAGE: …` 가 여러 줄에 걸치고 `━━` 줄로 닫힘)와 한 줄형 `[IMAGE: …]` 를 모두 센다. 원본 seo-calculator 정규식은 `]` 가 같은 줄에 있는 마커만 세는 버그가 있어 박스형을 빠뜨린다 — 백오피스에 저장된 옛 점수와 비교할 때만 `--legacy-image-count` 로 원본 동작을 재현하고, 그때는 차이가 이미지 개수에서 난다고 설명한다.

## 출력 형식
```
## SEO 점수 — {제목}
{normalizedScore}/100 · {통과|수정 필요|발행 불가} · 루브릭 {CAT-…} · 상태 {S?} ({n}개 항목, {total}/{max}점)

| 항목 | 실측 | 기준 | 점수 | 상태 | 힌트 |
|---|---|---|---|---|---|
| 제목 길이 | 29 | 25~30자 | 10/10 | ✅ | |
| 키워드 빈도 | 7회 | 3~5회 | 10/15 | ❌ | 키워드 과다 사용 — 5회 이하로 줄이세요 (현재 7회) |

(발행 불가일 때) 발행 불가 — SEO 점수가 50점 미만입니다. S3(발행예정) 이상에서는 50점 이상이어야 발행 가능합니다.

### 18항목 체크리스트
필수 {x}/10 · 권장 {y}/4 · 선택 {z}/3 → {판정} (사람 확인 대기: 9, 10, 12, 18)
| ID | 항목 | 결과 | 근거 |
```
점수 색은 텍스트로 "초록/주황/빨강"이라 적는다.

## 금지·주의
- 점수·글자수·키워드 수를 손으로 세어 보고하지 않는다. 스크립트 결과만 쓴다.
- 레거시 18항목 판정은 미확인 항목을 미통과로 센다 → 사람 확인 항목이 남아 있으면 항상 "발행 불가"가 나온다. 이것을 글 품질 문제로 오해하게 쓰지 말고 "확인 대기"임을 분명히 한다.
- 18항목 기준(json)과 자동 점수 루브릭은 일부 수치가 다르다(본문 2,500 vs 2,000자, 이미지 7 vs 5장, 태그 "정확히 10" vs "10개 이상+100자 미만"). 점수·판정은 루브릭을 따르고, 차이를 물으면 `references/seo-checklist-18.md` §3 표로 설명한다.
- 결과를 기록할 때: Notion "디딤 블로그 콘텐츠" DB 에는 SEO 점수 전용 필드가 없다. 사용자가 원하면 해당 글의 '메모'에 "SEO 72 (2026-10-01, 수정 필요)"처럼 한 줄 남기고, 커넥터가 없으면 대화에 출력한다.
- 본문을 직접 고치지 않는다. 힌트만 준다(본문 수정은 didim-blog-writer, 사실 수정은 didim-blog-factcheck).
- 품질 점수는 같은 달 글들의 최댓값 대비 상대 점수다. 비교 대상 없이 한 글만 주면 그 글이 100점이 되므로, 월 목록이나 월 최댓값을 함께 받는다.
